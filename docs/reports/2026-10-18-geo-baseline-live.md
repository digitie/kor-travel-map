# Geo 기준점 실제 UI 수용 기록 — 2026-10-18

## 확인 결과

n150 Chromium 1228에서 실제 관리자 로그인 후 Geo 릴리스 화면의 수동 감지를 두 번 실행했다.
8개 검사가 모두 통과했다. 최초 감지는 baseline_recorded로 plan 1을 만들었고, 같은 지문에서
다시 감지했을 때 baseline과 같은 plan 1을 반환했다. 최종 목록은 한 건이며 상세 API의
items도 0건이다. 목록 API의 빈 items만으로 작업 수를 판정하지 않았다.

로그인·안정된 현재 토큰/초기 계획 없음·1365px/390px 화면·최초 감지·동일 토큰 재감지·
동일 기준점 상세 검증·로그아웃을 검사했다. 수동 감지 요청은 정확히 두 번이며 예상하지
않은 쓰기 요청은 0건이다. [공개 검증 근거](2026-10-18-geo-baseline-live.safe.json)에
시각·검사 항목·하니스와 원본 증거의 SHA256을 보관했다. 인증값·원본 응답·사설주소는 제외했다.

## 배포 및 선행 조건

실행 전 API·코드 서버·UI가 running/healthy이고 세 이미지의 revision label은
e937b38d176cfeb759daca629395f51c1a6a4d5f였다. 이 값은 실행 중 이미지 라벨 관찰이며
이번 검사의 전체 설치 파일 해시 증명은 아니다. DB의 실제 Alembic head는
409_geo_release_item_reasons였다. 이미 적용된 제품이므로 이번 문서화에서 재빌드나
마이그레이션을 반복하지 않았다.

선행 Geo 배포 후 활성 지문을 공식 CLI로 한 번 저장했다. 파생 테이블 region_radius_parts를
제외한 8개 원천 테이블 지문과 data_token은 n150의 읽기 전용 계산 결과와 일치했다.
Geo DB 저장값과 API 값의 일치도 확인한 다음 이 UI 검사를 실행했다.

검사 전후 Dagster daemon은 중지 상태, 현재 run과 물리 worker는 각각 0이었다.
Map 컨테이너의 image/PID/restart/running 식별값도 유지됐다. 기준점은 실제로 저장되어
있으므로 초기 계획이 없다는 전제로 하니스를 재실행하거나 기준점을 삭제하지 않는다.

## 남은 검증과 해석

이 결과는 최초 기준점과 동일 지문 재실행의 실제 수용이다. 실제 지문 변경 후 replay,
중간 실패 resume, dirty/export 후속 완료, 자동 센서/dequeue의 운영 수용으로 확대하지 않는다.
사용자의 daemon 중지 지시를 유지했다. MOIS 전체 수집이나 가짜 지문 주입은 하지 않았다.
수집 CPU·메모리 비교 실측도 이 UI 검사의 범위 밖이다.

제품·DTO·스키마·설정 변경이 없는 문서 PR이다. 사용자의 문서 PR CI 생략 지시에 따라
CI를 실행하지 않으며, CI 미실행을 성공으로 기록하지 않는다.
